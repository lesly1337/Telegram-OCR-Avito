# Telegram OCR Avito Agent 🤖🔍

Локальный Telegram-бот-агент для автономного сбора данных с Avito и OCR-обработки изображений. Проект использует локальную LLM (Ollama) для понимания естественного языка и извлекает структурированные данные (IMEI, SN, MAC, пароли) без использования облачных AI-API.

## 🎯 Цель проекта
Разработать автономного агента, который:
1. Принимает запрос на естественном языке (например, «найди 15 iphone 13, нужны sn и imei»).
2. Уточняет параметры (если нужно).
3. Парсит выдачу Avito и скачивает изображения.
4. Выполняет локальный OCR.
5. Извлекает целевые сущности (IMEI с валидацией по Луну, MAC-адреса, SN, пароли).
6. Формирует и отправляет пользователю XLSX-отчет.

**Ключевое требование:** Полная автономность, отсутствие внешних AI-API (OpenAI, Anthropic и т.д.), работа через Docker Compose.

---

## 🏗 Архитектура

- **Telegram UI:** `aiogram 3` (асинхронный, FSM).
- **NLU (Понимание запросов):** `LangChain` + `Ollama` (локальная модель `qwen2.5:7b-instruct`).
- **Парсинг Avito:** `Playwright` (обход защиты) + `curl_cffi` (скачивание картинок).
- **OCR:** `pytesseract` + `EasyOCR`.
- **Извлечение данных:** Регулярные выражения + проверка по алгоритму Луна.
- **База данных:** `SQLite` (`aiosqlite`) для кэша, задач и сущностей.
- **Отчеты:** `pandas` + `openpyxl`.

### 🧪 Проверка OCR на fixtures (3 ноября 2026)

Эталонные значения были вручную прочитаны с изображений и проверены по алгоритму Луна. Новые фотографии проверялись тем же OCR-пайплайном на области этикетки. Большие входные фотографии теперь предварительно уменьшаются до Full HD; повторный EasyOCR каждой строки всё ещё требует оптимизации.

| Fixture | Эталонные IMEI | Результат OCR | Итог |
| --- | --- | --- | --- |
| `test_image.jpg` (Samsung) | `354484225821337`, `355064225821336` | Оба номера, без ложных IMEI | 2/2 |
| `test_iphone12.jpg` | `356692119126062` | `356692119126062`; конфликтующий `256692110126062` отклонён голосованием | 1/1, без false positive |
| `test_iphone13.jpg` | `359577623313115`, `359577623387234` | Неподтверждённые Luhn-кандидаты отклонены | 0/2, без false positive |
| `test_iphone_12_pro.jpg` | `353369280623390`, `353369280526718` | Оба номера; ложный `253360280526718` отклонён голосованием | 2/2, без false positive |

Серийные номера на новых изображениях видны вручную (`F17DMS5WD091`, `DJSFPG4F0D`, `F2MDRPZP0D53`), но текущий пайплайн их не извлёк. Формат Apple `(S) Serial No.` и ошибки OCR в буквенно-цифровых значениях требуют отдельной доработки. Полные 32-значные EID намеренно не считаются IMEI.

Текущая проверка показывает, что одного Luhn недостаточно: ошибочно распознанная последовательность тоже может случайно пройти проверку. Поэтому итоговый IMEI требует согласия движков либо нескольких контекстных OCR-вариантов. Это повысило точность, но не восстанавливает номер, если ни один движок не распознал его корректно, как на `test_iphone13.jpg`.

## 🚀 Как запустить (на текущий момент)

1. **Клонировать репозиторий:**
   ```bash
   git clone https://github.com/lesly1337/telegram-ocr-Avito.git
   cd telegram-ocr-Avito
   python3 -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   ```

2. **Запустить тесты извлечения:**

   ```bash
   pytest -q
   ```

3. **Проверить поиск объявлений и фотографий:**

   ```bash
   python test_avito.py "iphone 13" --limit 3
   ```

   Скрипт открывает найденные объявления в одной сессии браузера и выводит ссылки на их фотографии. Если Avito попросит пройти проверку, установите в `.env` значение `AVITO_HEADLESS=false` и выполните проверку в открывшемся браузере. При отсутствии карточек или фотографий скриншот страницы сохраняется в `data/tmp/avito_debug.png` (или в настроенный `TMP_DIR`).
