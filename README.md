# Telegram OCR Avito Agent

Telegram-бот ищет объявления на Avito, распознаёт текст на фотографиях и отправляет XLSX-отчёт с найденными IMEI, серийными номерами, MAC-адресами и паролями. Запрос разбирает локальная модель Ollama; изображения обрабатываются локально с помощью EasyOCR и Tesseract. Для Telegram, Avito, загрузки зависимостей и моделей требуется сеть.

Пример запроса: `найди 3 iphone 13 на avito, нужны imei и sn`.

## Как это работает

1. Telegram-бот принимает текст и передаёт его в Ollama. При ошибке модели или таймауте в 40 секунд исходный текст используется как поисковый запрос.
2. Создаётся задача в SQLite. Playwright открывает поиск Avito через `PROXY_URL`, собирает ссылки и идентификаторы объявлений.
3. Для объявления проверяется кэш по `avito_id`. Если данных нет, бот получает до пяти фотографий, запускает EasyOCR и Tesseract и извлекает значения регулярными выражениями; IMEI дополнительно проверяется алгоритмом Луна.
4. Бот формирует XLSX со ссылкой, заголовком, полями SN, IMEI, MAC, «Пароль» и пятью колонками фотографий, после чего отправляет файл в Telegram.

Распознанные поля из запроса пока не фильтруют колонки отчёта: бот всегда формирует все четыре типа. Уточняющие вопросы и ограничение доступа по списку администраторов пока не реализованы.

## Что уже проверено

- Образ Docker собран; внутри него проверены запуск Chromium, модели EasyOCR и языки Tesseract.
- Telegram подключён через отдельный VPN-прокси, Avito — через `PROXY_URL`. После ручной проверки Avito пользователь подтвердил работоспособность.
- SQLite-кэш, формирование XLSX, обработка блокировки Avito и команды диагностики реализованы. Состояние автоматических тестов и ограничения описаны ниже.

## Требования

- Docker Engine и Docker Compose; для графической проверки из контейнера в Windows проверен WSL2 с WSLg и Docker Desktop.
- Достаточно места и оперативной памяти: образ включает PyTorch, Chromium и модели EasyOCR, а модель `qwen2.5:7b-instruct` занимает несколько гигабайт. Первая сборка скачивает большие пакеты и может занять продолжительное время.
- Токен Telegram-бота, полученный у BotFather.
- Доступный путь к Telegram API. Если прямое подключение недоступно, нужен HTTP CONNECT или SOCKS5-прокси.
- При необходимости — прокси с российским выходным IP для Avito. Российская геолокация не гарантирует, что Avito не запросит проверку.

EasyOCR в текущем коде работает на CPU (`gpu=False`). При сборке стандартные зависимости PyTorch могут включать большие CUDA-пакеты, даже если GPU не используется.

## Настройка `.env`

Клонируйте проект, если его ещё нет на компьютере, и перейдите в его каталог:

```bash
git clone https://github.com/lesly1337/telegram-ocr-Avito.git Telegram_OCR_Avito
cd Telegram_OCR_Avito
```

Создайте `.env` из примера, если файла ещё нет:

```bash
cp -n .env.example .env
```

Откройте `.env` в редакторе и задайте как минимум `BOT_TOKEN`. Для прокси используйте адреса своего провайдера; пример ниже содержит только placeholders:

```dotenv
BOT_TOKEN=123456:replace-me
PROXY_URL=http://user:password@proxy-host:port
TELEGRAM_PROXY_URL=
TELEGRAM_DOCKER_PROXY_URL=http://host.docker.internal:10809
OLLAMA_MODEL=qwen2.5:7b-instruct
OLLAMA_HOST_PORT=11435
```

Не добавляйте в репозиторий настоящий `.env`, токен, пароли или конфигурацию прокси с учётными данными. `.env`, `3proxy.cfg`, `data/` и файлы базы исключены из Git; `.env` и данные также исключены из контекста сборки. При компрометации токена или пароля замените их у соответствующего провайдера.

### Маршруты прокси

| Переменная | Назначение |
| --- | --- |
| `PROXY_URL` | Прокси только для поиска Avito через Chromium и загрузки фотографий через `curl_cffi`. Пустое значение означает прямое подключение. |
| `TELEGRAM_PROXY_URL` | HTTP (`http://`) или SOCKS5 (`socks5://`) прокси Telegram для локального запуска. Пустое значение означает прямое подключение. |
| `TELEGRAM_DOCKER_PROXY_URL` | Необязательный адрес Telegram-прокси именно для Docker Compose. Если он задан, Compose передаёт его боту вместо `TELEGRAM_PROXY_URL`. |

Для VPN на Windows, предоставляющего HTTP-прокси на порту `10809`, в Docker Desktop был проверен адрес `http://host.docker.internal:10809`. Порт и доступность зависят от приложения. VPN должен быть включён. Для Telegram Bot API нужен HTTP CONNECT или SOCKS-прокси: MTProto-прокси из настроек клиентского приложения Telegram здесь не подходит.

`host.docker.internal` предназначен для контейнера Docker Desktop. При запуске Python непосредственно в WSL это имя может быть недоступно, а `127.0.0.1` указывает на саму WSL, а не обязательно на Windows. Для локального запуска задайте в `TELEGRAM_PROXY_URL` адрес, реально доступный из WSL.

В логине и пароле прокси специальные символы нужно кодировать как компоненты URL: например, `@` → `%40`, `:` → `%3A`, `$` → `%24`. Адрес российского прокси не заменяет Telegram-прокси. Compose не устанавливает общий прокси для всего приложения; Ollama доступна по внутренней сети Docker. Старый файл `3proxy.cfg`, если он есть локально, в текущем Compose не используется.

### Остальные настройки

| Переменная | Назначение |
| --- | --- |
| `OLLAMA_MODEL` | Модель для разбора запроса; по умолчанию `qwen2.5:7b-instruct`. Её нужно скачать отдельно. |
| `OLLAMA_BASE_URL` | Адрес Ollama для локального запуска; по умолчанию `http://localhost:11434`. В Compose переопределяется на `http://ollama:11434`. |
| `OLLAMA_HOST_PORT` | Порт контейнера Ollama на хосте; по умолчанию `11435`, чтобы не конфликтовать с локальной Ollama на `11434`. |
| `AVITO_BASE_URL` | Базовый адрес Avito. |
| `AVITO_MAX_ITEMS_DEFAULT` | Лимит объявлений, если модель не определила количество; по умолчанию `30`. |
| `AVITO_HEADLESS` | Режим локального браузера. Compose принудительно включает headless; ручная проверка описана ниже. |
| `TESSERACT_CMD`, `TESSERACT_LANG` | Путь к Tesseract и языки; в контейнере используется `/usr/bin/tesseract`, языки по умолчанию `rus+eng`. |
| `DB_PATH`, `TMP_DIR` | Путь к SQLite и каталог временных файлов; по умолчанию `./data/app.db` и `./data/tmp`. |
| `LOG_LEVEL` | Уровень логирования; по умолчанию `INFO`. |

`ADMIN_IDS`, `AVITO_REQUEST_DELAY`, `AVITO_USE_FIXTURES` и `OCR_MAX_IMAGES_PER_ITEM` присутствуют в настройках, но текущий основной пайплайн их не применяет. Доступ к боту сейчас не ограничивается через `ADMIN_IDS`. Число фотографий задаётся константой `MAX_PHOTOS = 5` в `app/main.py`. Профиль браузера сейчас закреплён за `data/browser_profile`; изменение `DATA_DIR` автоматически не переносит профиль, базу или временные файлы.

## Запуск через Docker Compose

Выполняйте команды из корня проекта:

```bash
docker compose build
docker compose up -d ollama
docker compose exec -T ollama ollama pull qwen2.5:7b-instruct
docker compose up -d bot
docker compose ps
docker compose logs -f bot
```

Если в `OLLAMA_MODEL` указана другая модель, скачайте именно её. Если Ollama ещё запускается и команда `pull` не подключается, повторите её через несколько секунд. Модель хранится в Docker volume `ollama_data`; SQLite, профиль браузера и отчёты — в `./data`.

Откройте бота в Telegram, отправьте `/start` и затем поисковый запрос. При старте бот удаляет webhook с `drop_pending_updates=True`, поэтому старые ожидающие сообщения могут быть отброшены.

Повторный запуск и остановка:

```bash
docker compose up -d
docker compose logs -f bot
docker compose stop
```

После изменения кода или зависимостей пересоберите образ: `docker compose up -d --build bot`. После изменения `.env` примените настройки командой `docker compose up -d bot`: обычный `restart` не пересоздаёт контейнер с новым окружением. `docker compose down` удаляет контейнеры и сеть, но не именованный volume без `-v`; не удаляйте volume, если хотите сохранить модель.

Хостовый порт Ollama — `127.0.0.1:11435` по умолчанию; изменить его можно через `OLLAMA_HOST_PORT`. Внутри сети Compose бот продолжает обращаться к `ollama:11434`.

## Проверка подключений

В работающем контейнере:

```bash
docker compose exec -T bot python -m scripts.check_proxy_routes
```

Или, если бот остановлен, после сборки:

```bash
docker compose run --rm --no-deps --entrypoint python bot -m scripts.check_proxy_routes
```

Команда вызывает Telegram `getMe` и получает страну выходного IP Avito через `ipwho.is`, не печатая адрес, логин или пароль. Она не открывает Avito, не проходит капчу и не обновляет профиль браузера. Если `PROXY_URL` пуст, проверка страны сообщает, что он не задан; скрипт возвращает ненулевой код и при стране, отличной от `RU`. Сам бот при пустом `PROXY_URL` всё равно пытается подключиться к Avito напрямую.

В локальном окружении та же команда запускается как `python -m scripts.check_proxy_routes` и проверяет `TELEGRAM_PROXY_URL`, а не Docker-специфичный `TELEGRAM_DOCKER_PROXY_URL`. Геолокация IP приблизительная: результат `RU` не проверяет репутацию адреса и не гарантирует доступ к Avito.

## Ручная проверка Avito в Docker Desktop и WSLg

Обычный контейнер запускает Chromium без окна. Если бот сообщает об ограничении IP или Avito просит пройти проверку, можно открыть тот же профиль и тот же прокси в видимом браузере. В WSL из корня проекта выполните:

```bash
bash scripts/verify_avito.sh
```

В открывшемся окне нажмите кнопку проверки Avito, пройдите её вручную и закройте браузер. Скрипт временно остановит бота, если он работал, и запустит его снова после закрытия окна или ошибки. Затем повторите запрос боту. Остановка предотвращает одновременное использование одного профиля; во время проверки не отправляйте боту новые запросы.

Профиль хранится в `data/browser_profile` и передаётся контейнеру через `./data`. Привязка файла скрипта в команде позволяет запустить проверку даже без пересборки старого образа. Для другой графической системы может понадобиться иная настройка DISPLAY и сокета. Если IP прокси изменится или Avito снова запросит проверку, процедуру может понадобиться повторить.

На практике проверка может повторно появляться через пару часов. Профиль уже сохраняется между запусками, но решение о новой проверке принимает Avito; однократное прохождение навсегда гарантировать нельзя. Причина повторения пока не установлена: стоит проверить стабильность выходного IP и сохранность профиля, а также исследовать влияние срока действия данных сессии, частоты запросов и различий между видимым и headless-браузером. В будущем можно уменьшить частоту проверок и улучшить уведомление о них; наличие подходящего официального API для нужного сценария тоже стоит изучить.

## Локальный запуск без Docker

Пример для Ubuntu/WSL с Python 3.12:

```bash
sudo apt-get update
sudo apt-get install -y python3-venv tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python -m playwright install --with-deps chromium
```

Установите и запустите Ollama локально, затем скачайте модель:

```bash
ollama pull qwen2.5:7b-instruct
python scripts/check_env.py
python -m app.main
```

Для локального бота нужны доступные из WSL Telegram-прокси и Avito-прокси из `.env`. Включите VPN, если его использует Telegram. Не запускайте одновременно локальный бот и бот в Docker с одним токеном: оба попытаются получать обновления Telegram. Локальный браузер и контейнер также не должны одновременно открывать `data/browser_profile`.

Локальные диагностические команды:

```bash
python test_ollama.py
python test_avito.py "iphone 13" --limit 3
python test_ocr.py
```

`test_avito.py` обращается к реальному Avito; `test_ocr.py` использует `fixtures/test_image.jpg`. Для ручной проверки в Docker используйте отдельную команду выше. Скриншот последней проблемной страницы сохраняется в `data/tmp/avito_debug.png` или в настроенном `TMP_DIR`.

## Кэш, база и отчёты

SQLite создаётся автоматически при старте. Таблица `jobs` хранит задачи, `listings` — объявления с уникальным `avito_id`, `entities` — найденные значения; схема также содержит таблицу `images`.

При повторном поиске сохранённого объявления бот повторно скачивает фотографии для Excel, но пропускает OCR и берёт сущности из кэша. Объявление без идентификатора не кэшируется. Новые результаты не сохраняются, если фотографий нет или хотя бы одна из выбранных фотографий не скачалась.

У кэша пока нет срока действия или автоматического обновления при изменении объявления. Ошибка OCR может вернуть пустой текст и при успешно скачанных фотографиях всё равно попасть в кэш. Сохраняйте резервную копию базы перед ручным изменением данных.

Отчёты и промежуточные изображения остаются в `data/tmp`; автоматической очистки пока нет. Они, база и профиль могут содержать распознанные идентификаторы, пароли и данные браузера — учитывайте это при передаче файлов и резервном копировании.

## Частые трудности

**Avito показывает «Доступ ограничен» или HTTP 439.** Прокси может работать и определяться как российский, но Avito может ограничивать конкретный выходной IP или требовать проверку. Проверьте `PROXY_URL`, стабильность IP и следуйте разделу ручной проверки. При необходимости запросите у провайдера другой выходной адрес. Скриншот последней страницы — `data/tmp/avito_debug.png`.

**`ipwho.is` показывает NL.** Контейнер может использовать указанный прокси, а его выход при этом определяться как Нидерланды. Проверьте страну и настройки у провайдера; после изменения `PROXY_URL` пересоздайте контейнер бота. Диагностический скрипт проверяет страну, но не доказывает, что Avito примет адрес.

**Telegram не подключается.** Убедитесь, что VPN или отдельный Telegram-прокси включён и доступен из того окружения, где работает бот. Для Docker Desktop проверьте `TELEGRAM_DOCKER_PROXY_URL`; локальный `127.0.0.1` внутри контейнера не означает Windows. Затем выполните проверку подключений и посмотрите `docker compose logs -f bot`.

**Окно проверки не появляется.** При обычной работе Docker запускает браузер без окна. В WSL проверьте наличие WSLg и выполните отдельную команду из раздела ручной проверки. Если профиль занят, остановите бота и повторите попытку.

**Ollama недоступна или запрос понят неверно.** Проверьте `docker compose ps`, логи Ollama и `docker compose exec -T ollama ollama list`. При ошибке модели бот использует исходный текст как запрос, поэтому результат может отличаться от ожидаемого.

**Занят порт `11434` или `11435`.** По умолчанию контейнер использует на хосте `11435`, а локальная Ollama часто занимает `11434`. Если и `11435` занят, задайте свободный `OLLAMA_HOST_PORT` в `.env` и выполните `docker compose up -d ollama`.

**Playwright не устанавливается при сборке.** Встречалась ошибка apt с `ttf-unifont` и `ttf-ubuntu-font-family`: плавающий `python:3.12-slim` перешёл на Debian 13, а Playwright 1.49.1 выбрал неподходящие пакеты. Dockerfile закреплён на совместимом `python:3.12-slim-bookworm`; Python-зависимости и Chromium устанавливаются отдельными слоями. Если ошибка повторится, проверьте полный лог сборки.

**Compose предупреждает об orphan-контейнере `3proxy`.** Это может быть контейнер от прежней конфигурации. Текущие сервисы Compose его не используют; само предупреждение не мешает запуску бота.

**`Using CPU` или предупреждение PyTorch о quantization.** В текущей конфигурации EasyOCR работает на CPU, а предупреждение само по себе не означает ошибку. Если бот завершился, проверьте сообщения об ошибке и статус контейнера.

**Фото или данные отсутствуют в Excel.** Avito может не отдать изображения, загрузка может завершиться ошибкой, а OCR или регулярные выражения могут не распознать текст. Проверьте логи, скриншот и исходные фотографии; пустое значение отображается как `-`.
